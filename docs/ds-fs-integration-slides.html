01 · Mengapa perlu dipisah?

Dashboard bukan sekadar mengambil data lalu membuat grafik

×

Jika semua dihitung backend

FS harus menentukan rumus bisnis, membersihkan data, membuat ranking, dan memeriksa kualitas. Peran DS tidak terlihat.

VS
✓

Jika memakai pipeline DS

DS menghasilkan data laporan yang sudah bersih dan siap tampil. FS fokus pada API, keamanan, dan tampilan.

Tujuan bersama: satu definisi data, satu hasil yang konsisten, dan pembagian kerja yang dapat dinilai dari checklist.
02 · Pembagian sederhana

DS memasak data, FS mengantarkan hasilnya

DS

Data Science

Mengambil data, membersihkan, memvalidasi, menghitung metrik, membuat insight, dan menerbitkan snapshot.

BE

Backend FS

Membaca snapshot DS, menjaga autentikasi, menerima filter, lalu mengirim JSON melalui API.

FE

Frontend FS

Menampilkan card, tabel, grafik, filter, status loading, dan pesan ketika data belum tersedia.

Batas penting: backend boleh membaca tabel hasil DS, tetapi tidak menghitung ulang Top 10, revenue, atau pelanggan unik dari tabel transaksi.

04 · Alur data langkah demi langkah

Dari klik customer sampai grafik tampil

1Customer booking

Customer mengisi layanan, jadwal, alamat, dan jumlah unit.

2FS menyimpan

Backend memvalidasi input lalu menyimpan transaksi ke MySQL.

3Worker DS membaca

Proses latar belakang membaca perubahan data secara otomatis.

4DS membersihkan

Timestamp diubah ke WIB, duplikasi dan nilai kosong diperiksa.

5DS menghitung

Top 10, revenue, status teknisi, dan pelanggan unik dihitung.

6DS mempublikasikan

Hasil siap tampil ditulis ke tabel snapshot secara utuh.

7API membaca

Backend memilih snapshot sesuai periode dan filter pengguna.

8React menampilkan

Grafik dan tabel muncul tanpa menghitung ulang data bisnis.

05 · Apa yang dikerjakan DS?

DS mengubah data transaksi menjadi data laporan

✓Konversi waktu UTC menjadi Asia/Jakarta
✓Mengeluarkan booking berstatus cancelled
✓Memeriksa booking duplikat dan nilai kosong
✓Menggabungkan booking dengan layanan dan teknisi
✓Mengisi bulan tanpa transaksi dengan angka nol
✓Membuat kombinasi filter layanan dan customer
# File milik DS
facts = extract_facts(connection)
validate_facts(facts)

rows = build_snapshots(
    facts,
    as_of=tanggal_hari_ini
)

publish_snapshots(connection, rows)

07 · Periode dan filter

Filter hanya bekerja pada laporan yang relevan

Periode global

3, 6, atau 12 bulan untuk kelima laporan.

Filter lokal

Layanan dan customer khusus untuk Teknisi serta Booking Terjadwal.

Customer dipilih

Seri “Pelanggan Unik” disembunyikan karena hanya satu customer dianalisis.

Tidak ada transaksi

Grafik tetap memiliki bulan lengkap dengan nilai nol.

Ilustrasi: FS hanya menerima angka siap tampil dari API.

11 · Local dan production

Satu perintah untuk developer, otomatis untuk production

Saat belajar atau menguji data, DS boleh menjalankan pipeline manual. Di production, Task Scheduler, cron, atau worker service yang menjalankannya.

# Local — dijalankan tim DS
cd C:\xampp\htdocs\cp\nara-ac\data-science
\.venv\Scripts\python.exe \
  business_report_pipeline.py

# Production — scheduler setiap 5 menit
# user/customer tidak melihat proses ini
Jika pipeline gagal: snapshot terakhir tetap dipakai. Sistem mencatat error dan tim menerima pemberitahuan; customer tetap dapat melakukan booking.

13 · Cara kerja mahasiswa

Urutan kerja yang ringan untuk setiap perubahan laporan

1Sepakati pertanyaan

Contoh: layanan apa yang paling sering dipesan dalam 6 bulan?

2DS tulis definisi

Tentukan sumber tabel, status yang masuk, rumus, dan grain.

3DS buat pipeline

Tambahkan pengolahan serta test untuk kasus normal dan kosong.

4Sepakati JSON

DS dan backend menyetujui nama field dan tipe data.

5Backend membaca

Backend membuat endpoint aman tanpa mengubah angka.

6Frontend menampilkan

Pilih chart, tabel, tooltip, dan filter yang relevan.

7Bandingkan hasil

Cocokkan output DS, response API, dan angka pada layar.

8Catat temuan

Tulis arti hasil dan rekomendasi untuk pemilik UMKM.

14 · Definisi selesai

Satu angka, satu definisi, tiga tim yang selaras

DS bertanggung jawab pada kebenaran dan arti data. Backend menjaga akses dan kontrak. Frontend membuat hasilnya mudah dipahami.

Data dapat dipercaya

Ada validasi, test, waktu pembaruan, dan definisi yang tertulis.

Integrasi dapat dirawat

Perubahan rumus tidak tersebar di backend dan frontend.

User tetap sederhana
